# ADR-059 — Return envelope, `workflow_report` and role-filtered skills

## Status

Accepted — **replaces** [ADR-009](009-inter-agent-handoff-contracts.en.md) (`*-handoff-format` skills); **evolves** [ADR-015](015-concision-posture.en.md) (concision postures) and [ADR-016](016-execution-path-skills.en.md) (`-standalone` / `-subagent` skills); builds on [ADR-042](042-checkpoints-headless-decisions.en.md) (decision cards) and [ADR-043](043-session-bundle-deploy-removal.en.md) (session bundle)

## Date

2026-11-02

## Context

[ADR-009](009-inter-agent-handoff-contracts.en.md) formalised the returns between agents as eleven `*-handoff-format` skills (one per producer-consumer pair), injected on both sides, with a `## Retour vers <consumer>` block that carried the whole report. The coordinator had to **retranscribe** that block (skill `retranscription-coordinateur`, about 2,000 tokens per coordinator) before deciding. In use:

- **The report went through the coordinator's mouth**: retranscription and summaries lost information (reviewer corrections, wiki enrichments), and cost the tokens twice. The October 2026 modernisation report ([report](../../dev/rapport-modernisation-2026-10.md), § 7.2 and decisions C, § 12) calls it a structural flaw and decides to replace the formats by an envelope, a small payload per agent and `workflow_report`.
- **Producer and consumer were mixed** in the same skills: the formats travelled to both, and changing a field meant touching two frontmatters.
- **The title of the return named an agent written in a skill**, while the real caller depends on the workflow.
- **Two paths per agent** ([ADR-016](016-execution-path-skills.en.md)) and **two concision levels** ([ADR-015](015-concision-posture.en.md)) were each loaded from a separate file, selected by a `[SKILL:…]` marker the orchestrator had to remember to inject. The mechanism (`prompt-builder.sh`, `token_optimization.*` of `hub.json`) disappeared with script deployment ([ADR-043](043-session-bundle-deploy-removal.en.md)).

oh, for its part, now knows who calls whom (the workflow graph, [ADR-039](039-declarative-workflows-oh-v1.en.md)) and keeps a state per session (daemon, [ADR-047](047-session-interaction-daemon.en.md)).

## Decision

### 1. A short envelope, a report stored by oh

- **Envelope** (`skills/shared/handoff-envelope.md`, for an agent launched by another): 15 lines at most, starting with `## Retour vers <caller>`: agent and status, report id (`rp-<n>`), `### Questions bloquantes`, `### Suite proposée`, `### Résumé` (3 lines), `task_id`. The detail goes in the report, not in the envelope.
- **Report**: the agent files it whole with the `workflow_report` tool (`title`, `body`) of the `workflow` MCP server, **before** the envelope. oh keeps it (`~/.oh/sessions/<session>/reports/`, metadata and hash in the database) and answers `rp-<n>`. The author is the agent oh sees calling the tool, never a value given by the agent. Limits: 64 KiB per report, 100 reports and 4 MiB per session. `workflow_report_get` reads a report (or a section, by Markdown heading), `workflow_reports` lists them.
- **The coordinator no longer retranscribes**: it reads the envelope, reads the report (or a section) with `workflow_report_get` when it needs it, passes the **id** (or the section as it is, never a summary of its own) on to the next agent, and cites the reports in `reports` of `workflow_checkpoint`. The checkpoint card attaches the reports filed since the previous one, the timeline shows them, `oh session report` gives them to the user; in a remote session they come back in the `reports.json` artifact.
- **Fallback**: without the daemon (or with `OH_WORKFLOW_REPORTS=off`) the tool answers "not recorded" without an error; the envelope then carries `**Rapport** : inclus` and the whole report follows below the envelope.
- **No `question` for a subagent**: the user does not see its calls. The bundle removes the tool from it (`QuestionGuard`); its questions go to `### Questions bloquantes`, its caller asks them and resumes it with the `task_id`.

### 2. A payload per agent, a generated contract

- Each agent that returns an envelope has a small `<agent>-payload` skill (200 to 400 tokens, bounded by a test): its **statuses** (`statuses:` in the frontmatter) and the **sections of its report**.
- The **session contract** of each agent, generated by oh from the graph, names its callers (the `## Retour vers <caller>` title comes from there) and, for a coordinator, the table of return statuses of the agents it may launch.

### 3. Role variants are filtered at build time

Instead of loading two skills and injecting a marker, a skill or a paragraph carries `when: role=entry` or `role=subagent` (`<!-- oh:when … -->`) and oh ships each agent only what applies to its role in the workflow. Consequences for earlier decisions:

- the `-standalone` / `-subagent` pairs ([ADR-016](016-execution-path-skills.en.md)) become a single `execution-protocol` with one section per role;
- the concision postures ([ADR-015](015-concision-posture.en.md)) become `core-posture` (common), `user-facing-posture` (entry agents) and `coordinator-posture` (coordinators); the goal of ADR-015 (go straight to the point without losing information) is kept in `core-posture`, with no `lite` or `subagent` levels and no configuration key.

## Consequences

### Positive

- No more retranscription: the coordinator only consumes the envelope, and the tokens of the reports are paid once.
- Nothing is lost between the agent and the user: the decision card, the timeline, `oh session report` and resumption show the original report.
- One return format instead of eleven; changing the sections of an agent only touches its payload.
- Agents no longer have to think about `[SKILL:…]` markers: the role comes from the workflow.

### Negative / trade-offs

- **Dependency on the tool and the daemon**: without them the "included" fallback puts the report back in the reply (the former behaviour, for that case only).
- Reports are bounded (64 KiB, 100, 4 MiB); beyond that the tool refuses and the agent includes the report.
- A report is kept in `~/.oh/sessions`: agents only read or write it through the tools (`~/.oh/sessions` is refused by the oh guards).
- Agent behaviour depends on reworked prompts: only `oh eval`, with a real model, measures it.

## Alternatives considered

| Alternative | Rejected because |
|-------------|------------------|
| Keep the `*-handoff-format` skills and lighten them | The flaw is structural: the report goes through the coordinator, and the format is shared between producer and consumer |
| Report in a project file | Pollutes the repository, depends on the agent's file system, does not survive a remote session |
| Report in Beads (ticket comment) | Not every workflow has a ticket, and size is limited |
| Drop the envelope and return only the id | The coordinator would have neither status nor blocking question to decide on routing |
| Shared state file between agents | Already rejected by [ADR-009](009-inter-agent-handoff-contracts.en.md): file-system coupling, non-reproducible session |

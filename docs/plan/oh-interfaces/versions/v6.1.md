# Plan — v6.1 : non-devs et distribution (P4)

> **Sessions de travail : lire ce fichier et [regles.md](regles.md).**
> Plan global : [../00-plan.md](../00-plan.md).
> Version : **6.1**. Durée : environ 4,5 à 6 semaines. **À reprendre quand de vrais utilisateurs non-devs arriveront** ; les décisions ci-dessous sont encore ouvertes.

## Décisions à prendre au début

| # | Question | Recommandation |
|---|---|---|
| F1 | opencode : téléchargé au premier lancement, ou intégré à l'app ? | Téléchargé, avec une version fixée et le checksum vérifié |
| F2 | Kit d'accueil d'équipe ? | Selon le public : oui si un administrateur prépare la config des non-devs |
| F3 | Cloner un projet depuis GitLab dans l'app ? | Selon le public (identifiants git, ADR-057) |
| F4 | Mode équipe pour les non-devs : masquer complètement Git ? | Selon le public (+2 à 3 semaines) |

## Lots

| Lot | Contenu | Durée |
|---|---|---|
| 61-tools | `oh tools install` : opencode et beads aux versions validées, checksum vérifié, dans `~/Library/Application Support/OpenHub/tools/` ; `oh` est configuré pour les utiliser ; git passe par `xcode-select --install` | 1,5 à 2 sem |
| 61-onboarding | Assistant d'accueil dans le web et l'app (étapes de `oh init` de la 5.9) : langue, outils, fournisseur, projet (sélecteur de dossier), équipe ; `doctor` lisible avec des actions | 1,5 sem |
| 61-kit | (si F2) Kit d'accueil d'équipe : export signé par un administrateur (fournisseur et région sans secret, équipe, projets, workflows épinglés), import en trois clics ; base existante : `oh provider import`, `oh team member join` | 1 à 2 sem |
| 61-dist | Compte Developer ID ; signature et notarisation dans la CI macOS ; Sparkle (l'app et son `oh` mis à jour ensemble, après la fin des sessions actives) ; cask `datichb/tap/openhub-app` | 1 à 1,5 sem |

## Plus tard (hors de cette version)

- Tauri pour Windows et Linux (même front ; WebView2 et WebKitGTK déjà testés par Playwright).
- Onglet « Terminal avancé » (xterm.js) dans l'app.
- App « client seul » connectée à un `oh` distant (ADR-062 § 8), qui suppose une vraie authentification et TLS.

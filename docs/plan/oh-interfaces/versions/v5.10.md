## État de départ

- `oh serve` : `cmd/serve.go`, `serve_api.go`, `serve_html.go` (`dashboardHTML`), `serve_sse.go` (relecture toutes les 5 s), `serve_auth.go` (jeton, cookie, Host, S-36), environ 1 500 lignes ; 11 routes `/api/v1` en lecture seule.
- Le regroupement du board de `serve_api.go` passe par `appsvc/board` depuis la 5.8.
- Le bus d'événements (`appsvc/events`) a une séquence et une reprise depuis la 5.6.
- `ohd` : `~/.oh/run/ohd.sock`, vérification de l'UID du pair (`internal/daemon/peer*.go`), démarrage à la demande (`daemon/client.Ensure`).

Parallélisme : `510-stream ∥ 510-wizards`, puis `510-client`, puis `510-tui ∥ 510-web-cmd`.

## Points de vigilance

- **Écritures simultanées** : vérifier avec deux clients que la détection de conflit (config, claims, board) renvoie `conflict` avec la version actuelle, et que les événements arrivent aux deux clients.
- **Écritures non atomiques** restantes : il ne doit en rester aucune sur le team-state, le board ou la config (fait en 5.5 si D5 = oui ; sinon, le faire ici).
- **Sécurité** : repasser les tests de `serve_auth_test.go` (DNS rebinding, Host, cookie) sur `uiserver` ; aucun secret dans les URL ; vérifier les droits du socket.
- **Si la latence en mode client est trop forte** : le TUI garde le mode direct par défaut, et seuls le web et l'app passent par `uiserver`. Le reste du plan ne change pas.

# Plan — v6.0 : interface web, app macOS et retraits de la v6

> **Sessions de travail : lire ce fichier, [regles.md](regles.md) et l'ADR-063** (`docs/architecture/adr/063-*`). Pour les lots web, ajouter le fichier OpenAPI généré.
> Plan global : [../00-plan.md](../00-plan.md).
> Version : **6.0** (version majeure : nouvelles interfaces, et retraits annoncés depuis la v5). Durée : environ 10 à 12 semaines.

## Objectif

1. Une interface web locale pour les personnes peu à l'aise avec le terminal : décisions, sessions, lancement, résultats, board, wiki, accueil, projets.
2. Une app macOS (usage local, `.dmg` avec signature ad hoc).
3. Les retraits annoncés pour la v6.

## Lots web (Vue 3, TypeScript, Vite)

| Lot | Contenu | Durée |
|---|---|---|
| 60-web-base | Projet Vue (pnpm, version de Node fixée) ; Reka UI et shadcn-vue (Tailwind), thème repris de `internal/tui/theme` ; vue-query avec un client SSE qui invalide les requêtes ; Vue Router (portée dans l'URL) ; Pinia minimal ; vue-i18n alimenté par `fr.json`/`en.json` (conversion `%s` → `{x}`) ; types générés par `openapi-typescript` et `openapi-fetch` ; composant `<SchemaForm>` (formulaires de la 5.9) ; page de remplacement committée `internal/webui/dist/index.html` ; `make web` ; étapes préalables de goreleaser et Node dans `release.yml` ; **CI front** (lint, types, Vitest, `eslint-plugin-vuejs-accessibility`, Playwright sur Chromium et WebKit avec axe-core, audit des dépendances) | 2 sem |
| 60-web-sessions | **Décisions** (checkpoints, questions, permissions en un clic) et **Sessions** (sections, détail, suivi en direct, envoi, arrêt, reprise) ; conversation : ouverture d'opencode dans le navigateur (mode `pair`) | 2 à 2,5 sem |
| 60-web-launch | **Lancer** : projet, workflow, tickets, entrées, récapitulatif (`LaunchDraft`) | 1,5 sem |
| 60-web-results | **Résultats** : diff (diff2html), coût, rapport (markdown-it et DOMPurify), description de MR | 1 sem |
| 60-web-board | **Board** : colonnes, cartes, prise et déplacement, avec **déplacement au clavier** (« Déplacer vers… », `aria-live`) en plus de vue-draggable-plus | 1,5 sem |
| 60-web-misc | **Wiki** (propositions, pages), **Accueil**, **Projets** (liste, ajout) ; palette de commandes (catalogue `Commands`) | 1,5 sem |

**Accessibilité** : cible WCAG 2.2 AA ; une violation axe fait échouer la CI ; tout se fait au clavier ; les mises à jour en direct sont regroupées avant d'être annoncées aux lecteurs d'écran ; `prefers-reduced-motion`, `prefers-contrast`, focus visible.

## Lot app macOS (Swift, 1,5 à 2 semaines)

- [ ] App SwiftUI avec une WKWebView ; `WKURLSchemeHandler` `oh://` relié à `~/.oh/run/ui.sock` (pas de port, pas de jeton) ; adresse du serveur configurable.
- [ ] `oh` intégré (Intel et Apple Silicon) dans `Contents/Helpers/` ; démarrage de `uiserver` par ce binaire.
- [ ] PATH lu dans un shell de connexion.
- [ ] Barre des menus avec le badge `● N ⏸ M` ; badge sur l'icône du Dock ; **notifications natives avec boutons** (valider, refuser, voir : BL-11 et BL-22) ; sélecteur de dossier natif ; lancement à l'ouverture de session ; sortie conforme à l'ADR-047 § 5 ; présence et focus (ADR-062).
- [ ] « Installer la commande `oh` » (lien symbolique) ; avertissement si un autre `oh` (Homebrew) a une version différente.
- [ ] `make app` → `.dmg` avec signature ad hoc ; compilation sur le runner macOS de la CI.

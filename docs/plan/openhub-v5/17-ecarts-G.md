## Lot N22-b — jeton de hook (S-06), garde de fermeture (S-09), environnement de `bd` (S-14)

- S-14 confirmé : `cmd.Env` absent (environnement complet du démon) ; jetons de sous-agents valides jusqu'à la fin de la racine ; `gateway.json` relu sans contrôle.

**Choix (adaptation de DC24, sans décision nouvelle)** :
- **Jeton de hook à usage unique émis par le démon**, demandé par le **faux bd** (et non par le hook) : quand `BD_GIT_HOOK=1` et `hooks run …`, le faux bd local appelle `POST /v1/gateway/hook-token` **sur le socket du démon** (chemin donné par le `bd` des sessions locales, `OH_BD_DAEMON_SOCKET`, `cmd/v5_beads_local.go`), avec son jeton `ohg_`. Le démon lit le **PID du pair** du socket (`LOCAL_PEERPID` macOS, `SO_PEERCRED` Linux ; `ConnContext` du serveur, une ligne dans `daemon.go`) et remonte l'arbre des processus (nouveau paquet `internal/procinfo` : `kern.proc.pid` + `kern.procargs2` macOS, `/proc` Linux) : un ancêtre doit exécuter le fichier `<git rev-parse --git-path hooks>/<hook>` de l'emplacement de la session, et un ancêtre de celui-ci doit être `git`. Jeton `ohh_…` (30 s, une seule commande, lié à la session, au sous-agent et au hook) placé dans `ExecRequest.HookToken`. La passerelle n'accorde le mode hook qu'avec ce jeton ; sinon refus 403 traduit (`cmd.gateway.beads.hook_unverified`), commit bloqué (échec fermé).
- **Forme exacte** (repli de DC24, appliqué en plus) : `hooks run <hook>` sans aucune option, avec les arguments que git passe (`pre-commit` : 0 ; `prepare-commit-msg` : 1–3, source connue, sha si `commit` ; `post-merge` : `0|1` ; `post-checkout` : sha sha `0|1` ; `pre-push` : 2). Autre forme = commande ordinaire (liste `beads.allow`).
- **Systèmes sans lecture des processus** (Windows, autres) : jeton donné après la seule vérification de forme (repli DC24) — **écart** : sous Windows, `BD_GIT_HOOK=1 bd hooks run post-merge 0` lancé par un agent reste possible (n'exécute que ce que git ferait).
- **Limite assumée** (principe 2) : un agent qui fait exécuter le hook par git lui-même (`git -c alias.x='!sh .beads/hooks/post-merge 0' x`, ou une vraie opération git autorisée : `git merge`, `git pull`, `git checkout -b`) obtient le jeton : il n'obtient que ce que git ferait, avec les arguments de git. L'écriture de `.beads/*.jsonl` (qui rendrait `post-merge` dangereux) est refusée par `BeadsDirGuard` (lot a).
- Route ajoutée par une ligne dans `daemon/handlers.go` (**zone de S**, constante `hookTokenRoute` définie dans `daemon/hooktoken.go` pour ne pas toucher aux imports) ; non privilégiée (la capacité de la CLI n'est pas disponible au faux bd), authentifiée par le jeton `ohg_` + l'arbre des processus.
- Conteneur et job distant (mode journal) : hooks toujours ignorés (rien ne tourne), sans jeton.
- **Garde de fermeture (S-09)**, `services/checkpoint/locks.go` : nouveau `Service.Work` (défaut `GitWork`) ; fermeture acceptée seulement si HEAD ≠ commit du checkpoint, ce commit est ancêtre de HEAD (`merge-base --is-ancestor`), `git diff <cp> HEAD -- . ':(exclude).beads'` non vide, et arbre propre. Commit du checkpoint inconnu (`""`) : accepté seulement si aucun commit n'est antérieur au passage (`rev-list --before`), diff depuis l'arbre vide ; sinon refus (`errUnknownStart`). Toute erreur git → refus (`locked_git`) ; le démon refuse aussi toute erreur non `LockError` de la garde (`guard_failed`). **Changement de comportement** : « rien à committer » ne permet plus de fermer un ticket verrouillé par un checkpoint (un ticket sans modification de code doit être fermé par l'utilisateur, ou par un workflow sans `unlocks: [close]`). `state.go` (zone de S) non modifié ; champ `Work` ajouté dans `service.go` (3 lignes).
- **Environnement minimal de `bd`** (`beadsEnv`) : `PATH`, `HOME`, `USER`, `LOGNAME`, `SHELL`, `LANG`, `LC_*`, `TZ`, `TMPDIR`/`TEMP`/`TMP`, `NO_COLOR`, `XDG_*`, `BEADS_*` (sauf `BEADS_DIR`, fixé par oh), variables système de Windows, et `OH_BD_MODE|SNAPSHOT|JOURNAL` (job distant). Les hooks enchaînés par bd ne reçoivent donc plus les variables du démon (déjà sans les `GIT_*` du hook, limite connue de T2).
- **Jetons de sous-agents** : révoqués à `EventExecEnded` de la sous-session, redonnés (environnement complet de la racine) à son `EventExecStarted` suivant (`watcher.endChildGrant/resumeChildGrant`, 2 lignes dans `watch.go`, champ en fin de struct). - **`gateway.json` vérifié au redémarrage** : fichier régulier, sans droits pour les autres (sauf Windows), ≤ 16 Mio, **signé** (HMAC-SHA256 avec une clé dérivée de la capacité du démon, `OpenSignedStore`) ; entrées mal formées ignorées. Signature absente ou fausse → aucune autorisation reprise. **Écart** : après la mise à jour d'oh, le premier redémarrage du démon ignore le fichier non signé : les sessions ouvertes retrouvent Beads à leur reprise (`oh session resume`), annoncé dans le CHANGELOG.

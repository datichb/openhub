## Critères d'acceptation
1. Créer `ticket-hotfix` (extends `hub:ticket`) dans l'équipe, le valider, le tester en brouillon, le publier ; un autre membre le voit après sync et le lance.
2. Fichier publié modifié à la main ⇒ ignoré + avertissement (catalogue, Doctor).
3. Deux publications concurrentes ⇒ la seconde rebase, revalide et publie v+1.
4. Projet sans équipe : création de workflow possible via l'espace solo ; `team promote` sans perte.
5. Migration des configs workflow existantes sans perte (tests sur fixtures).
